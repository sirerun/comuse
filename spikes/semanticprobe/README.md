# Fixture semantic projection probe

This standard-library-only package normalizes the current native AX observation response. It performs no AX I/O, event posting, persistence, or tool/API serving. The host supplies the expected request ID, process PID/bundle/nonce/launch generation and opaque process/window references. The native envelope contains only process-start and window references; the other scope fields remain trusted host inputs and are not independently attested by this normalizer.

`NormalizeEnvelope` accepts the bounded v1 shape from `AccessibilityProbe.swift`: the outer schema/request/status and a result containing observation/state IDs, opaque refs, an ordered forest of element refs/roles/identifiers/value statuses, and coverage counts. It validates exact scope refs, strict fields, tree links/order, and the fixed 256-node, 16-depth, 16 KiB text and 250 ms native coverage limits. Native expired/stale errors remain typed denials. Inconsistent, unknown or truncated coverage never becomes a complete snapshot or infers deletions. Serialized snapshot status is the string `complete` or `partial`.

The output has two separate identities. `NativeStateID` is retained only as an opaque exact native precondition when coverage is complete and projected values match the explicit request; it is excluded from ordinary JSON serialization. `CanonicalStateID` hashes a fixed-order semantic projection after redaction. The canonical projection binds stable fixture bundle ID and nonce, ordered parent/child topology, roles, identifiers, normalized value status, coverage and, only with explicit opt-in, `textfield`/`AXTextField` synthetic text plus `counter-value`/`AXStaticText` synthetic counter text. It excludes random observation/process/window/element refs, raw native hashes, geometry and all other values. Secure and otherwise unapproved values are stripped before canonicalization. Partial snapshots carry neither identity.

The normalizer cannot determine from JSON alone whether a caller-supplied PID, launch generation, role or target classification still matches the live OS. Trusted native owner code must revalidate those identities before using refs or admitting writes.
